## 经验

以下是一些进行Schema调整的成功经验

~~~
场景: 两个或多个表之间频繁进行等值连接，且连接条件中涉及的列选择性高，查询需要匹配的行是唯一的（一对一或一对多）。

操作: {"type":"TableJoin","left_table":"T1","right_table":"T2","join_keys":["k1","k2"],"join_type":"natural","select_columns":["T1.k1","T1.c1","T2.k2","T2.c2"],"new_table":"T1_T2_JOIN","keep_original":true}
说明: join_keys 必须为非空数组；select_columns 必须用 left_table.col 或 right_table.col 形式；join_type 与 keep_original 的规则一致。

效果: 减少高频连接操作的执行开销，降低查询延迟。

场景: 一个非常宽的表，少数几列被高频查询，而另一些列或被低频访问。
